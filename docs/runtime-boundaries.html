程程工作台：正式 Runtime 边界

North Star：Microsoft Scout 是唯一正式 Runtime，也是唯一通知控制面；OpenClaw 退出生产数据链，只保留代码开发工具身份。

职责矩阵

组件正式职责明确不负责
Microsoft ScoutTeams Bot 入口、用户身份、Skills、Automations、模型与工具权限、运行历史、全部通知不绕过工作台审批状态，不把群聊自然语言直接当工程命令
程程工作台本地 Dashboard、SQLite 当前状态、工程提案、决定、幂等与审计不主动查询云端，不在 v0.5 执行工程变更
Scout Runtime Root迁入的确定性脚本、领域 Skills、证据、独立配置与运行产物不依赖 OpenClaw session、memory、cron 或 message delivery
OpenClaw迁移期间代码开发、测试与版本管理；旧 Cron 在切换前暂时生产对照数据切换完成后不承担 Teams Remote、调度、数据生产、审批执行或通知

迁移状态机

INVENTORIED → PACKAGED → SCOUT_DISABLED → SHADOW_GREEN → CUTOVER_APPROVED → SCOUT_OWNER → OPENCLAW_DISABLED → VERIFIED

Fail closed：每条链独立切换。Scout 至少连续 3 次产生与旧链同口径、同日期、完整证据且无副作用的结果后，才允许请求停用对应 OpenClaw Cron。通知切换必须验证 Scout Teams Bot 收到后再关闭旧通道，避免空窗。

隔离要求

  • 正式脚本不得引用 ~/.concordia-client。
  • Scout 使用独立 Runtime Root、Azure Config、SQLite、logs、evidence 和 document root。
  • 凭据不进 Git；只使用 Scout/OS 已批准的 Secret Provider 或独立本机认证。
  • OpenClaw 与 Scout 在 Shadow 期不能同时执行外发或 ADO 写入；Shadow 必须强制 no-send / no-write / no-notify。
  • 切换后成功、失败、审批和摘要通知全部只发送到 Scout Teams Bot；禁止 OpenClaw 微信、OpenClaw announce、邮件 owner 通知或双重 Teams 发送。
  • 每条 Automation 显式配置 workingDir、skillNames、permissions、shadow teamsNotify 和 cutover teamsNotify。
